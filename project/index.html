02

The 70/30 Philosophy

Here's the truth: Cursor can write code faster than you can type. The scarce skill isn't coding—it's knowing what to build and why.

70%
Thinking & Design

Problem identification, value proposition, analytics approach, user journey, business case. This is where you demonstrate strategic thinking.

30%
Building & Shipping

Working Streamlit app deployed to the web. Cursor handles the heavy lifting—you direct.

🎯 What This Means For You

Don't spend 80% of your time debugging code. Spend 80% of your time thinking about:

  • What problem is worth solving? Who cares about this?
  • What data would power this solution? Where would it come from?
  • What's the prescriptive analytics logic? Optimization? Prediction → Recommendation?
  • How would a user interact with this? What decisions does it help them make?
  • Why would someone pay for this? What's the business case?

Then use Cursor to bring your vision to life. That's how products get built.

Example Ideas by Track

Track A: Optimization Examples

  • Staff Scheduler: Optimize employee shifts given availability, skills, and labor laws
  • Ad Budget Allocator: Distribute marketing spend across channels to maximize ROI
  • Inventory Optimizer: Determine reorder points and quantities across SKUs
  • Course Scheduler: Assign classes to rooms and time slots optimally

Track B: Analytics + Insights Examples

  • Churn Predictor: Identify at-risk customers and recommend retention actions
  • Sales Forecaster: Predict demand and suggest inventory actions
  • Resume Analyzer: Score resumes against job requirements with improvement suggestions
  • Financial Health Checker: Analyze spending patterns and recommend budget adjustments
  • Content Recommender: Suggest products/content based on user behavior analysis

Track C: Decision Intelligence Examples

  • Investment Lighthouse: Profile investors through questions → recommend suitable stocks with reasoning
  • Career Pathfinder: Assess skills and goals → recommend career moves and learning paths
  • Vendor Selector: Guide users through requirements → score and rank suppliers
  • Location Advisor: Gather business requirements → recommend optimal locations with tradeoff analysis
  • Treatment Recommender: Collect patient symptoms → suggest diagnostic paths (educational)
💡
The "Lighthouse Investor" Idea We Discussed: A decision intelligence tool that asks 3-5 sequential, optimized questions to profile an investor, then uses that profile to recommend stocks with business analytics reasoning. This is a great Track C example—it combines profiling (prediction), optimization (question sequencing), and prescription (stock recommendations with rationale).

FAQ

Can I work with a partner?

This is an individual project. You can discuss ideas with classmates, but the concept, code, and documentation must be your own work.

What if I can't get Gurobi working?

Use scipy.optimize instead—it's what the Portfolio Optimizer uses by default. For many problems, scipy is sufficient. Don't let tooling block you.

How polished does the app need to be?

It needs to work and demonstrate the concept. Beautiful UI is nice but not required. A functional app with a great README beats a pretty app with no documentation.

Can I use AI tools like ChatGPT, Claude, or Cursor?

Yes—enthusiastically! Using AI to code is expected and encouraged. That's the "vibe coding" approach we've been practicing. Just make sure you understand what your code does and can explain your approach.

What if my optimization model doesn't give perfect results?

That's fine. Real-world analytics is messy. What matters is that you can explain the model, show it runs, and discuss its limitations. Honest reflection on what works and doesn't is valuable.

Can I use a dataset from my job or personal life?

Absolutely—domain expertise makes for better projects. Just ensure you're not violating any confidentiality agreements. Anonymize if needed.

What if I don't have real data for my idea?

Options: (1) Find a public dataset that's close enough, (2) Create synthetic/sample data that demonstrates the concept, (3) Use APIs for live data (like yfinance for stocks). The README should explain your data strategy including how a production version would source data.

Is the video really necessary?

Yes. It's only 3-5 minutes and it demonstrates communication skills—a key differentiator in analytics careers. Employers want to see you can explain technical work to stakeholders. Plus, it gives your project personality.

What if Streamlit Cloud deployment fails?

Common issues: (1) Missing dependencies in requirements.txt, (2) File paths that work locally but not in cloud, (3) Large files that exceed limits. Check the Streamlit docs for troubleshooting. If truly stuck, reach out with the error message.

Can I change my idea midway through?

You can, but be careful—pivoting late eats into build time. Better to lock a "good enough" idea early than to keep searching for the "perfect" idea. Start building and iterate.
